# AI Cognitive Switchboard

**AIはスイッチを要求できるが、自分で通電できない。**

AI Cognitive Switchboardは、AIが使う記憶、外部知識、推論モード、問いセット、人間レビュー条件を切り替えるための制御プロトコルです。AIは設定の変更を提案できます。認可は対象AIの外側で行い、信頼されたコントローラーが設定を反映し、その結果を確認します。

「認知」が指すのは、モデルの内部ではなく実行環境の設定です。たとえば、同じAIを通常の応答から監査向けの処理プロファイルへ切り替えても、そのAIに新しいデータやツールへのアクセス権が付くわけではありません。

- プロトコルバージョン `0.1`
- リポジトリ `ai-cognitive-switchboard`
- ステータス 仕様化中

## v0.1の5つのスイッチ

| スイッチ | 値 | 役割 |
| --- | --- | --- |
| `memory` | `OFF` / `READ_ONLY` / `READ_WRITE` | 管理対象の永続記憶へのアクセスを切り替える。`OFF` は会話履歴の削除を意味しない |
| `external_brain` | `OFF` / `ON` | 登録済みの外部知識アダプターを選択する。通信やデータアクセスを認可しない |
| `reasoning_mode` | `default` / `creative` / `skeptical` / `audit` | 版を固定した推論プロファイルを選択する |
| `question_pack` | `null` または登録済みID | 版を固定した問いセットを選択する。`null` は無効を表す |
| `human_review_required` | `true` / `false` | 設定の有効化と、その設定下の保護された操作に人間レビューを要求するかを示す |

設定は5項目をまとめて扱います。省略による継承はせず、承認済みの設定と実際の設定が完全に一致した場合だけ `active` にできます。部分適用は成功ではありません。

## 要求・認可・適用を分ける

| 段階 | 何が起きるか |
| --- | --- |
| 要求 `requested` | 対象AIなどが変更を求める。この時点では設定は変わらない |
| 認可 `authorized` | 人間、固定ポリシー、または認可権限を持つ外部コントローラーが、対象・設定・適用範囲・期限を確認して認可する。この時点でも設定はまだ有効ではない |
| 適用 `active` | コントローラーが設定を反映し、結果が承認済みの設定と一致したことを確認する。その確認を記録してから利用を許可する |

たとえばAIが監査モードと外部知識の利用を要求しても、認可側は監査モードだけを認め、外部知識を `OFF` のままにできます。適用時に外部知識が `ON` になっていれば、監査モードへの切替自体ができていても有効化しません。

必要な根拠を確かめられなければ保留します。実行時ゲートは処理開始時と、記憶の書き込みなどの保護された操作の直前に、最新の有効状態、適用範囲、認可、期限、必要なレビューを確認します。期限切れ・失効・完了時は新たな保護操作を遮断します。以前の設定へ戻す場合も、その設定に対する現在の認可が必要です。

`human_review_required` は権限上の条件です。固定ポリシーや人間が要求したレビューをAIは省略できません。設定に対するレビューで、将来の個別操作まで一括承認されることもありません。

## リポジトリ構成

v0.1の最小構成です。README以外のファイルは順次追加します。

| パス | 内容 |
| --- | --- |
| `README.md` | 概要と責任範囲 |
| `specs/cognitive-switchboard-v0.1.md` | 役割、認可、状態遷移、適用と停止の正式仕様 |
| `schemas/switchboard-v0.1.schema.json` | スイッチボード記録のJSON Schema |
| `examples/valid-switch.json` | 認可を経て正しく適用された例 |
| `examples/denied-switch.json` | 要求を拒否し、設定を適用しなかった例 |
| `examples/unauthorized-activation.json` | 認可なしで適用した不正な例 |
| `scripts/validate.py` | サンプルの構造と意味を検査するスクリプト |
| `.github/workflows/validate.yml` | 各サンプルの検証結果が期待どおりかを確認するワークフロー |

## 検証の考え方

| サンプル | 期待結果 |
| --- | --- |
| `examples/valid-switch.json` | PASS — 認可と適用が整合している |
| `examples/denied-switch.json` | PASS — 拒否後に設定が適用されていない |
| `examples/unauthorized-activation.json` | FAIL — 認可なしに設定を適用している |

`denied` は運用上の判断です。`FAIL` は記録や遷移が仕様に違反しているという検証結果です。正しく拒否した記録はPASSであり、不正な例が期待どおりにFAILになれば、そのテストは成功です。

検証ファイルの追加後は、リポジトリのルートから `python scripts/validate.py` でサンプルを検査します。JSON Schemaで構造を検査し、値の一致や時刻の順序などは意味検査で確かめます。実際の主体認証、認可根拠、アダプターの状態、停止の確認は別の検証です。サンプルのCI通過だけで実行環境の適合を宣言しません。

## 対象外と今後の拡張

v0.1は、設定の認可・適用・停止を扱います。モデル内部の変更、推論品質の保証、外部書き込みやネットワーク権限の付与、課金、他プロトコルとの正式な相互運用は対象外です。

| 段階 | 範囲 |
| --- | --- |
| v0.1 | 固定5スイッチと、要求・認可・適用・停止の検証 |
| v0.2候補 | `reasoning_mode` に `companion` プロファイルを追加し、9状態の伴走型推論FSMと接続する。認知クラッチは、認可済みモード内の中断と再開を扱う |
| 比較実験後の候補 | HVIによる問い返し判定。問い返し回数と総コストを比較し、採用するかを判断する |

Switchboardが決めるのは、**どの設定を使ってよいか**です。伴走型推論FSMが決めるのは、**そのモード内でいつ問い返し、いつ推論を再開するか**です。問い返しへの返答は方向を更新する入力であり、失効した認可を復活させるものではありません。
